# Excel workbooks as calculations

Nightingale compiles an `.xlsx`/`.xlsm` workbook into an executable calculation: it reads formulas and Excel's saved values, separates **parameters** (cells a formula reads directly), **tables** (cells only read through ranges) and **results** (formulas no other formula reads), and runs each formula with Excel's semantics. **Workbooks** page, `/api/sheets/*` API and the `data_workbook` agent tool.

- `compile` (path or upload; macros never run), `evaluate` (new values by address, label or defined name; `as_of` for TODAY/NOW), `trace`, `check` (every formula against Excel's saved value), `verify` (seeded new cases recalculated by Excel through COM, or LibreOffice, compared result by result) and `export` (standalone Python module, standard library only, `compute()` and a command line).
- List validations become parameter options, including the cross-sheet ones Excel stores in an x14 extension.
- The source workbook's1900/1904 date system is retained in the model summary and used for constants, formula evaluation, formatted results, independent verification cases and standalone Python exports. Date contexts are isolated between concurrent calculations. Literal text beginning with `=` remains text; the OOXML cell type determines whether a cell is a formula.
- Independent verification with no cases or no eligible results is `inconclusive`, with zero comparisons; it does not run a reference engine or claim agreement.
- Anything outside the supported subset is **frozen** with Excel's saved value and listed with the reason; results depending on it are flagged `uses_frozen` and excluded from verification. Circular references are frozen (no iterative calculation).
- Evidence: random nested formulas recalculated by Excel, 3,073 of 3,093 equal (99.35%); approximate lookup fitted on 400 Excel observations on unsorted mixed data (descending 200/200, ascending 198/200). See `docs/WORKBOOK-COMPILER.es.md` for the function list and limits.

## Explain the calculation

Three views on the same compiled engine (no second set of formulas). Page **Workbooks** panels, `/api/sheets/{id}/sensitivity|scenarios|units`, and the `sensitivity`, `scenarios` and `units` actions of `data_workbook`. Every run is written to the analysis log.

- **Sensitivity** (`action="sensitivity"`, `output`, `delta`, `steps`): each numeric parameter is changed on its own by ±`delta` (default 10%) or by an absolute step given per parameter, the output is recalculated, and the parameters are ranked by swing (|output at high − output at low|) with their share of the total swing and the dominant one. Parameters that are not varied (text, booleans, dates, list options, a base of 0 without an absolute step) and cases whose output is an error or not a number are listed with the reason, never dropped. Parameters with no effect on the output are listed apart. Without `output`, every labelled result gets its own ranking.
- **Scenarios** (`action="scenarios"`, `op` = `list`, `save`, `delete`, `compare`): a scenario is a named set of parameter overrides (`scenario`, `inputs`, optional `note`) saved with the workbook. `compare` returns every labelled result for the base values and for each scenario (`scenario_names`, default all), with the absolute and relative delta against the base. A scenario that cannot be evaluated is reported in `failed`.
- **Units** (`action="units"`, `units` = `{cell or label: unit}`, null removes): units are declared on input cells and saved with the workbook; omit `units` to only report. Currency symbols and percent signs in number formats (`€`, `$`, `EUR`, `USD`, `%`) are read automatically (declared units win). Units are propagated through the formula AST with Pint: `+`, `−` and comparisons need compatible dimensions, `*` and `/` combine them (EUR/h × h = EUR), `SUM`, `MIN`, `MAX`, `AVERAGE`, `MEDIAN`, `ROUND*` and `ABS` keep the unit, the branches of `IF`/`IFERROR` must agree, and any other function gives an unknown unit (not an error). EUR and USD are separate base dimensions. The report lists the inferred unit of each formula cell and the unit errors (cell, formula, operation, both operand units); a cell with an error has no unit, so one mistake is reported once. Inputs without a unit are unknown and never produce an error. A plain number in a formula takes the unit of what it is added to or compared with, so `price + 5` is accepted.

Limits: units are not checked inside lookups, text functions or ranges that mix units (those stay unknown); percent and plain ratios are both dimensionless; the effects of changing one parameter at a time do not capture interactions between parameters.
